PART B - USER QUESTIONS, EASY ANSWERS
====================================

Q1. Project ka actual maqsad kya hai?
A. Weak Affine encryption ko demonstrate karna: encrypted local traffic
   se key recover karke messages parh sakte hain, is liye sensitive data
   ke liye yeh suitable security layer nahi.

Q2. Kya Gemini choose har baar karna parega?
A. Nahi. GEMINI_MODEL configuration mein selected model saved/pinned hai.
   Client test input select karta hai; model selection repeat nahi hoti.

Q3. Gemini ko encrypted Affine message jata hai?
A. Nahi. Local server Affine decrypt/de-armor karke application message
   readable banata hai, phir HTTPS/TLS-protected API request bhejta hai.

Q4. HTTPS bhi encrypted hai na?
A. Haan. Affine aur HTTPS two different layers hain. Server application
   readable text dekhta hai; network transport par TLS usay protect karta
   hai. Gemini side par TLS process hota hai, phir model text process karta.

Q5. Gemini response plaintext bhejta hai?
A. Server ko application-level readable reply milta hai AFTER TLS handling.
   Internet par reply unencrypted travel karne ka claim nahi. Local server
   phir us reply ko Affine encrypt karke client ko bhejta hai.

Q6. Phir tester kya karta hai?
A. Client<->local-server port9999 ke encrypted packets record karta hai.
   Frequency/key search se Affine key recover, then original text read.
   Gemini HTTPS connection break nahi hoti.

Q7. a,b se decrypt hota hai?
A. Haan. a,b key pair hai. Formula P=inverse(a)*(C-b) mod26. Pehle b
   subtract, then a ke modular inverse se multiply; ordinary a se divide
   karna modular arithmetic mein correct replacement nahi.

Q8. Key inverse kyun chahiye?
A. Encryption ka multiplication modular arithmetic mein undo karne ke liye.
   a*inverse(a) mod26=1. gcd(a,26)=1 se unique inverse exist karta hai.

Q9. 312 keys kyun?
A.26 ke saath12 coprime multipliers aur26 shifts:12*26=312.

Q10. E aur T hamesha top two letters hotay hain?
A. Nahi. They are useful reference hypotheses, not guaranteed identities.
   Actual candidate decryption English score aur independent checks matter.

Q11. Ham ne key secret file se read ki thi?
A. Attacker analysis server key import nahi karti. Separate verifier BAAD
   mein original key/input se compare karta hai. Client apni normal key
   se communication karta hai, jo real application ka intended behavior hai.

Q12. Mood key reveal karta hai to frequency attack kyun?
A. Frequency analysis assignment ka required demonstration hai. Cleartext
   mood schedule ek additional weakness hai, aur attack/verifier roles
   separate rakhe gaye hain taake explanation accurate ho.

Q13. Same text ka ciphertext har run same hoga?
A. Same plaintext and same Affine key ke liye yes. Lekin Gemini response
   wording vary ho sakti hai, so server ciphertext vary ho sakta hai.
   Same mood ki expected key pair phir bhi same rahegi.

Q14. Output kahan dikhega?
A. CLI task progress/PASS bottom VS Code Terminal mein. Generated charts,
