2. SIMPLE TERMS - VIVA KE LIYE
------------------------------
Plaintext: original readable message, misal "HELLO".
Ciphertext: encryption ke baad transformed message.
Key: encryption/decryption control karne wali values. Affine key pair (a,b).
Cipher: text encrypt/decrypt karne ka mathematical rule.
Encryption: plaintext ko ciphertext banana.
Decryption: ciphertext se plaintext wapas nikalna.
Packet capture: application ke actual network packets record karna.
Loopback: isi computer par local communication; IP 127.0.0.1.
Frequency analysis: har letter kitni baar aya, us pattern se substitution
samajhna. English mein E/T aksar common hain, magar har sample mein top two
zaroor E/T nahi hotay.

Affine cipher mein A=0, B=1, ... Z=25:
  Encryption: C = (a*P + b) mod 26
  Decryption: P = a_inverse*(C - b) mod 26
  gcd(a,26)=1 hona chahiye, warna unique inverse nahi milta.

Example: a=7, b=6, P='E'=4:
  C = (7*4 + 6) mod 26 = 34 mod 26 = 8 = 'I'
  inverse(7)=15 because 7*15=105=4*26+1.
  P = 15*(8-6) mod 26 = 30 mod 26 = 4 = 'E'.

Original server mood m se b=2*m aur a=next coprime integer above b leta hai.
Mood cleartext mein jata hai: yeh additional security weakness hai.
Frequency attack mood wali key rule use nahi karta; separate verification
script baad mein recovered key ko original rule se compare karta hai.

Input text pehle UTF-8 bytes se A-P letter pairs mein encode hota hai
(armor), phir encrypt hota hai. Is liye request ka histogram normal English
jaisa assume nahi karte. English server reply se key recover karte hain,
phir request decrypt aur de-armor karte hain.

9. COMMON VIVA QUESTIONS - SHORT ANSWERS
---------------------------------------
Q: 312 keys kyun?
A: 26 ke saath coprime 12 valid a values, aur 26 b values: 12*26=312.

Q: Key kaise recover ki?
A: Har server ciphertext par all valid keys test kiye; decrypted-letter
frequency ko English reference se chi-squared score kiya. Lowest score
candidate ko readable text, de-armoring, re-encryption aur independent
verification se confirm kiya. Isay frequency-guided exhaustive search
kehna accurate hai, sirf top two letters se blind guess nahi.

Q: E/T se equations?
A: Candidate mapping E->cE aur T->cT ho to 4a+b=cE, 19a+b=cT mod26.
Subtract: 15a=cT-cE mod26. inverse(15)=7, so a=7*(cT-cE) mod26.
Phir b=cE-4a mod26. Decryption ke liye a ka inverse use hota hai.

Q: Different sessions ko pool kyun nahi kiya?
A: Mood change hone se substitution/key change hoti hai. Har reply ka
histogram aur key separately analyze karna zaroori hai.

Q: Known plaintext aur repeated disclaimer ka kya role hai?
A: Predictable names/wording letter guesses de sakte hain. Agar product
fixed disclaimer add kare to woh strong clue hota hai. Is original server
mein fixed disclaimer enforce nahi hota; hum ne fake disclaimer add nahi kiya.

Q: Is this end-to-end secure?
A: Nahi. Affine weak hai, key schedule mood se reveal hota hai, server
plaintext dekhta/log karta hai aur Gemini ko prompt bhejta hai.

Q: Better security?
A: Local UNIX socket with restricted permissions + peer checks, ya TCP
over authenticated TLS 1.3. Self-signed certificate use ho to proper
trust/pinning chahiye; certificate checks disable nahi karne.
